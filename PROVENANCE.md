# Provenance Record: Correction History for "Attention-Gated Fusion for Modality-Robust Affective Computing"

This file contains the full account of a three-round correction process this manuscript went through before reaching its current state. The manuscript itself (`manuscript.md`) references this file and gives a short summary in the Abstract-adjacent disclosure box and in Section 5; this is the complete version for anyone who wants the full detail — an editor, a reviewer, or a reader deciding how much to trust the current numbers.

## Round 1: Fabricated results in Sections 3.1–3.2 and 3.4–3.6

An early version of this manuscript's Results section reported specific numbers — accuracy figures, p-values, a table of gate weights conditioned on mask presence, individual failure-case predictions — that were never produced by executing any code. They were written to illustrate what the results would look like once the pipeline was run, and were left in place as if they were real findings, complete with a specific borderline p=0.053 case and a gate-weight table carried to two decimal places.

**How this was caught:** not by review, self-audit, or any process designed to catch it. The code scaffold had been built out, and the author separately decided to actually run it end-to-end against real CMU-MOSI data. The real output directly contradicted the invented numbers — the central claimed effect reversed sign entirely and attached to a different model comparison than originally reported — which made the discrepancy impossible to miss. Had that execution step been skipped, the fabricated version would have stood as the manuscript's reported result.

**Correction:** Sections 3.1–3.3 were replaced with numbers generated by an actual run of `code_scaffold/run_experiment_grid.py`. Sections 3.4–3.6, which had no real underlying analysis at all, were removed rather than patched with new numbers invented to fit the corrected headline finding.

## Round 2: The Round 1 correction was itself incomplete

A subsequent exhaustive audit — checking every remaining numeric claim in the manuscript against its underlying data file, not just the sections already known to be fabricated — found three further problems:

1. **Table 3.3's FLOPs and Latency columns were invented.** No code in the pipeline ever measured or computed them. They sat in a table directly adjacent to the real, verified Params column, and were not caught by the Round 1 correction because that correction's scope was defined by "the sections we already know are fabricated," not by checking every table regardless of suspicion.
2. **Section 2.6 described a training-pipeline sanity check that never ran** ("verified to overfit a 16-sample subset... to near-zero loss within 50 steps"). No such check exists anywhere in the code.
3. **One real number was transcribed incorrectly**, not fabricated: `fixed_weight_fusion`'s parameter count was reported as 503,681 (matching several other models) when the true value, confirmed from `config_log.json`, is 470,913 — a ~7% error from careless transcription rather than invention.

**Correction:** the FLOPs/Latency columns were removed outright, not replaced with new estimates. The sanity-check claim was removed and replaced with an explicit statement that it was never run. The parameter count was corrected against `config_log.json`, and every downstream percentage computed from it was recalculated.

**Structural safeguard added:** `code_scaffold/verify_manuscript_numbers.py`, a script that recomputes every numeric claim in Sections 3.1–3.5 directly from the raw CSV/JSON files and reports PASS/FAIL for each. It was tested against a deliberately corrupted copy of `results_raw.csv` to confirm it actually fails when it should, not just when convenient.

## Round 3: Independent verification found a fourth, different-in-kind problem

A colleague/independent party ran a fresh AI session with no access to the manuscript, the author's code, or the verification script from Round 2 — only the five raw data files — and was asked to recompute every reported statistic from scratch before being shown the manuscript's claimed values.

It matched on every single number except one: Section 3.3's prose claim about which specific model produces the smallest vs. largest percentage-parameter-increase relative to the imputation baseline. The percentage range itself (+39–54%) was correct. The model *labels* attached to each end of the range were swapped: the manuscript had named `late_fusion` as the smallest-increase comparison and `fixed_weight_fusion` as the largest, when the actual smallest-increase model is `early_fusion`/`dropout_only_fusion` (+39.3%) and the actual largest is `late_fusion` (+54.3%).

This is a different kind of error than Rounds 1–2: nothing was invented, and every underlying parameter count feeding into it had already been independently verified correct. It was an error in composing a *derived, comparative* claim from otherwise-correct raw numbers — a failure mode the Round 2 verification script did not check for, because it checked individual values, not which label was attached to which end of a min/max range.

**Correction:** the sentence in Section 3.3 was fixed. `verify_manuscript_numbers.py` was extended with an explicit check for this exact failure mode — comparing not just percentage bounds but which model label is attached to each — and verified to correctly reject the original wrong claim and accept the corrected one.

## What this history does and doesn't mean for the current manuscript

Every numeric table currently in Sections 3.1–3.5 has now passed both a self-authored verification script and one round of independent (non-self) verification. That is real evidence the current numbers are trustworthy.

It is not proof of completeness. The verification script does not parse the manuscript automatically — its coverage is only as good as whether every new claim gets a corresponding check added at the time it's written, which is a process discipline, not a property of the tooling. Only the numeric tables and one derived comparative claim have had independent verification; the interpretive prose in Section 4's Discussion has only been checked by the manuscript's own author. The two open experimental items (encoder freeze/swap test, additional seeds) remain unrun.

Readers should weigh this history as: real evidence of a repeated, disclosed correction process, not as proof that no further error exists. Given that the process needed correcting twice before an independent check was even attempted, a degree of caution beyond the current PASS results is warranted, and is more defensible than treating this as fully closed.
